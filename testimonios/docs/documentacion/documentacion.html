Testimonios con React
Documentación de la práctica: de una tarjeta estática a una interfaz con estado y reproducción automática

Una aplicación de React creada con Vite que muestra testimonios de uno en uno. Se organizó el frontend en componentes, se transfirieron datos mediante props, se comunicaron los clics con callbacks y se actualizó la pantalla mediante estado. Después se amplió con reproducción automática usando useEffect. Cada etapa se verificó contra resultados esperados, y se provocó un error lógico a propósito para comprobar que las pruebas lo detectan.

1. Introducción y objetivo

1.1 El caso

Como visitante de un sitio web, quiero consultar testimonios de clientes mediante controles de navegación para conocer sus experiencias con el servicio. Los testimonios y fotografías son datos ficticios de demostración.

1.2 Objetivo

Construir la interfaz separando datos (data.js), presentación (Testimonial, Controls) y coordinación (App); explicar el recorrido desde index.html hasta los componentes visibles, y comprobar la navegación con casos normales, de límite y de datos.

Pregunta guía: ¿quién decide qué testimonio se ve? Respuesta: solo App, a través de su estado index. Los hijos reciben datos o funciones; ninguno guarda una copia del índice.

1.3 Resultado final

  • Se muestra una tarjeta con fotografía, nombre, cargo y comentario, además de la posición actual.
  • Anterior y Siguiente recorren todos los testimonios y conectan el último con el primero; Aleatorio nunca repite el actual.
  • Con un registro la interfaz funciona; con cero muestra un mensaje sin acceder a campos inexistentes.
  • El diseño se adapta a 320, 768 y 1280 px y los controles funcionan con teclado y conservan el foco visible.
  • Ampliación: avance cada cinco segundos con Pausar/Reanudar; la navegación manual detiene el avance.

2. Metodología de trabajo

Se siguió la guía en orden y sin adelantar pasos: primero la etapa básica y, solo cuando la navegación manual funcionó y quedó probada, la ampliación con temporizadores. Cada avance se guardó en un commit en la rama de trabajo del repositorio.

2.1 Rutina de cada paso

  1. Leer: qué cambia en el paso y qué resultado se espera, antes de escribir código.
  2. Editar: escribir el archivo indicado por la guía.
  3. Ejecutar: npm run dev y revisar en el navegador.
  4. Comparar: contrastar con la tabla de pruebas (P01–P10 o A01–A07).
  5. Guardar: commit con un mensaje que describe el avance.

2.2 Reglas que apliqué

  • Primero se define el resultado esperado y después se ejecuta.
  • Una sola modificación a la vez: en el error provocado solo cambió App.jsx; el script de pruebas quedó igual.
  • Los cambios temporales (P06, P07, índice [1], experimento de reutilización) se revirtieron antes del siguiente commit.
  • Las pruebas básicas se mantienen separadas de las de autoplay.

Paso 6 · Estado y navegación en App.jsx

Archivosrc/App.jsx
Comandonpm run dev
ResultadoAnterior, Siguiente y Aleatorio recorren los 3 registros
EvidenciaFiguras 5 y 6
const [index, setIndex] = useState(0);
const total = testimonios.length;

function next() {
  setIndex(actual => (actual + 1) % total);
}
function prev() {
  setIndex(actual => (actual - 1 + total) % total);
}
function random() {
  if (total < 2) return;
  const salto = 1 + Math.floor(Math.random() * (total - 1));
  setIndex(actual => (actual + salto) % total);
}

useState(0) devuelve el valor actual index y la función setIndex. El operador % envuelve los extremos; en prev se suma total para no obtener un número negativo. Aleatorio elige un salto entre 1 y total − 1, por eso nunca repite el actual. Si total === 0 se muestra un mensaje en lugar de la tarjeta (Anexo C).

Paso 8 · Ampliación: reproducción automática

Archivosrc/App.jsx
Comandonpm run dev
ResultadoAvanza cada 5 s; Pausar/Reanudar; navegar a mano pausa
EvidenciaFiguras 12 y 13
Commita670df3
const [reproduciendo, setReproduciendo] = useState(false);

useEffect(() => {
  if (!reproduciendo || total < 2) return;
  const intervalo = setInterval(() => {
    setIndex(actual => (actual + 1) % total);
  }, 5000);
  return () => clearInterval(intervalo);
}, [reproduciendo, total]);

function navegar(accion) {
  setReproduciendo(false);
  accion();
}

En el JSX se reemplazó Controls y se agregó el botón:

<Controls
  onPrev={() => navegar(prev)}
  onNext={() => navegar(next)}
  onRandom={() => navegar(random)}
/>
{total > 1 && (
  <button type="button" className="autoplay-toggle"
    onClick={() => setReproduciendo(actual => !actual)}>
    {reproduciendo ? 'Pausar' : 'Reanudar'}
  </button>
)}
<p className="counter">
  Testimonio {index + 1} de {total}
</p>
Decisión: El temporizador es un sistema externo al cálculo del JSX, por eso vive en useEffect y no en el cuerpo de App. La limpieza clearInterval evita intervalos acumulados. La reproducción inicia pausada para dejar leer, y se quitó aria-live del contador para no anunciar un cambio cada cinco segundos.

11. Preguntas de la guía

1. ¿Qué archivo contiene la tarjeta y qué recibe item?

Respuesta: src/components/Testimonial.jsx. item recibe un solo objeto testimonio; el hijo no necesita importar data.js porque App decide a quién mostrar y le pasa el objeto por props.

2. ¿Qué diferencia hay entre main.jsx y App.jsx?

Respuesta: main.jsx es el punto de entrada: conecta React con #root y monta la aplicación una vez. App.jsx es el componente raíz de la interfaz: importa los datos, conserva el estado y compone a los hijos.

3. ¿Qué tendría que copiar si no existiera Testimonial?

Respuesta: todo el bloque <article> con imagen, nombre, cargo y comentario en cada lugar donde se muestra una tarjeta; cualquier cambio habría que repetirlo en cada copia.

4. ¿Por qué no se escribe testimonios[index + 1] sin controlar el límite?

Respuesta: en el último registro index + 1 vale total, que no existe; el resultado es undefined y la tarjeta falla al desestructurar. Con % total el índice vuelve a 0. La sección 7.3 muestra el mismo problema en el límite inferior.

5. ¿Por qué el temporizador se maneja con un efecto y el clic con un evento?

Respuesta: el clic es una acción concreta del usuario y se responde cuando ocurre. El temporizador es una sincronización con un sistema externo (el reloj del navegador) que debe existir mientras se cumpla una condición (reproduciendo y al menos dos registros); eso es lo que describe useEffect.

6. ¿Qué problema evita clearInterval?

Respuesta: que se acumulen intervalos. Sin limpieza, cada Reanudar (o el montaje doble de StrictMode) crearía otro intervalo y el avance se aceleraría. A07 comprobó que tras alternar seis veces quedan 0 intervalos en pausa y 1 al reproducir.

7. ¿Por qué no existe un Hook llamado render?

Respuesta: renderizar no es algo que el componente pida: React ejecuta la función del componente cuando cambian su estado o sus props. El componente solo devuelve JSX. createRoot(...).render(<App />) es un método de la raíz para el montaje inicial, no un Hook.

8. ¿Qué cambiaría si el arreglo llegara de una API y pudiera actualizarse?

Respuesta: los testimonios pasarían a ser estado que empieza vacío, se cargarían en un efecto con fetch, habría que mostrar estados de “cargando” y “error”, y si cambia el tamaño del arreglo habría que asegurar que index siga siendo válido. La dependencia total del efecto ya permitiría volver a sincronizar el autoplay.

12. Reflexión final

Qué reutilicé. Testimonial sirve para cualquier persona: en el experimento se usó tres veces y un solo cambio en .testimonial-card se vio en todas. Sin el componente habría copiado el mismo bloque de JSX en cada lugar.

Comparación con actualizar el DOM a mano. Con JavaScript puro, cada clic tendría que buscar y cambiar la foto, el texto alternativo, el nombre, el cargo, el comentario y el contador, sin olvidar ninguno. En React describo la interfaz en función de index y React calcula qué cambia.

Qué depende de mi diseño y qué aporta React. Mío: separar datos, presentación y coordinación, decidir que el estado viva en App y cómo nombrar las props. React aporta el modelo de componentes, el estado, el renderizado y la confirmación en el DOM.

Un costo de React en una app pequeña. Requiere Node, npm, Vite, un paso de compilación y aprender JSX y Hooks. Una página con tres testimonios fijos podría resolverse con HTML, CSS y JavaScript.

Lo que me llevo. Las pruebas de inicio y de Siguiente pasaron aun con el error provocado; solo el caso de límite lo reveló. Por eso conviene probar casos normales, de límite y de datos (uno y cero registros), y ver fallar la prueba al menos una vez.

Una pregunta que todavía tengo. ¿Cómo decide React qué nodos del DOM reutilizar cuando una lista se renderiza con map, y por qué la key debe ser estable como item.id?

13. Conclusiones

  • Se completó el recorrido de la guía: datos → tarjeta → montaje → controles → estado → estilos → pruebas → autoplay → reutilización.
  • App conserva el índice, Testimonial presenta el registro y Controls comunica acciones mediante callbacks.
  • El operador % resuelve los extremos; sin + total el límite inferior produce un índice negativo y la tarjeta falla.
  • useEffect con su limpieza mantiene un solo intervalo activo; la navegación manual pausa el avance.
  • Se aprobaron P01–P10 y A01–A07, y npm run build compila sin errores.
  • Los problemas encontrados (plantilla distinta, foto remota, botón pegado y script que se detenía) se entendieron y resolvieron sin afectar el resultado.

Anexo C. Código final de App.jsx

1import { useEffect, useState } from 'react';
2import testimonios from './data.js';
3import Testimonial from './components/Testimonial.jsx';
4import Controls from './components/Controls.jsx';
5
6export default function App() {
7  const [index, setIndex] = useState(0);
8  const total = testimonios.length;
9  const [reproduciendo, setReproduciendo] = useState(false);
10
11  useEffect(() => {
12    if (!reproduciendo || total < 2) return;
13    const intervalo = setInterval(() => {
14      setIndex(actual => (actual + 1) % total);
15    }, 5000);
16    return () => clearInterval(intervalo);
17  }, [reproduciendo, total]);
18
19  function next() {
20    setIndex(actual => (actual + 1) % total);
21  }
22  function prev() {
23    setIndex(actual => (actual - 1 + total) % total);
24  }
25  function random() {
26    if (total < 2) return;
27    const salto = 1 + Math.floor(Math.random() * (total - 1));
28    setIndex(actual => (actual + salto) % total);
29  }
30  function navegar(accion) {
31    setReproduciendo(false);
32    accion();
33  }
34
35  if (total === 0) {
36    return <main className="app">
37      <h1>Experiencias de nuestros usuarios</h1>
38      <p>No hay testimonios disponibles.</p>
39    </main>;
40  }
41
42  return (
43    <main className="app">
44      <h1>Experiencias de nuestros usuarios</h1>
45      <Testimonial item={testimonios[index]} />
46      <Controls
47        onPrev={() => navegar(prev)}
48        onNext={() => navegar(next)}
49        onRandom={() => navegar(random)}
50      />
51      {total > 1 && (
52        <button type="button" className="autoplay-toggle"
53          onClick={() => setReproduciendo(actual => !actual)}>
54          {reproduciendo ? 'Pausar' : 'Reanudar'}
55        </button>
56      )}
57      <p className="counter">
58        Testimonio {index + 1} de {total}
59      </p>
60    </main>
61  );
62}
